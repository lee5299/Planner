# 구현 및 과제 제출 검증 체크리스트

## 사용 방법

- 참고: 사용자가 제공한 체크리스트.txt의 과제 6 통과 기준. 아래에 원문 ID와 기준을 모두 담아 이 문서만 전달해도 검증할 수 있게 한다.
- 모든 항목은 현재 미검증이다. 구현했더라도 실제 검증 전에는 [ ]를 유지한다. [x]는 증거가 있는 통과에만 사용한다.
- 항목별로 상태(미착수/진행/구현·미검증/통과/실패/차단), 검증일, 절차 또는 명령, 실제 결과, 증거 위치, WORK_LOG 항목을 기록한다. 공통 절차는 한 번 작성하고 관련 ID로 연결해도 된다.
- 기존 C01~C20과 원문 T06-Cxx는 서로 다른 ID 체계다. 중복 의미라도 삭제하거나 재번호하지 않는다. 원문에 없는 번호를 임의로 만들지 않는다.
- 완료한 기능과 과제 제출 준비를 구분한다. 실제 기록·사용자 판단·공개 URL은 AI가 만들어내지 않는다.

## 기존 기획과 적용 범위

- 과제 개발 계획시간 8~10h는 사용자 요청으로 제외한다. 개별 계획/업무의 예상 시간과 실제 수행 시간은 다른 개념이며 원문 기준으로 아래에 보존한다.
- 자기관리 화면에는 숫자 점수·달성률을 표시하지 않는다. 원문 숫자 집계·시간 비교·근거 기록 이동은 프로젝트 영역에 적용한다.
- 예상 시간, 실행 시작·종료 시각 및 실제 시간은 기존 PRD의 클릭 중심 기록보다 상세한 요구다. 체크리스트에 추가하되 기존 PRD의 시간 입력 비필수 방침을 몰래 바꾸지 않는다. 구현 시 프로젝트 상세의 선택 입력으로 제공하고 과제 검증 자료에는 채우는 방안을 우선 검토한다.
- 성공 기준, 업무별 우선순위·태그·검색·명시적 정렬, 전체 내보내기, 스키마 계약 파일은 원문에서 추가로 요구한 항목이다. 구현 전 PRD와 대응 관계를 동기화하고 미반영 상태를 WORK_LOG에 남긴다.
- 원문의 현재 상태 집계(T06-C28~C32)와 PRD의 과거 주 종료 시점 업무 정리는 기준 시점이 다르다. 현재 프로젝트 집계와 과거 주간 정리를 구분하고 각각 필터·기준 시점을 밝힌다.
- 삭제는 일반 목록/집계에서 제외하되 기존 PRD대로 이력은 보관한다. 지연 수는 서울 날짜로 계산하고 완료 항목을 중복 집계하지 않는다.
- 첫 화면 공개 안내는 T06-C82의 문구를 사용한다. 로그인·잠금은 이번 범위에 넣지 않는다.
- 결과물·소스 공개 URL은 제출 기준이며 이 문서 작성만으로 배포나 저장소 공개를 실행하도록 허가하는 것은 아니다.

## 카드별 검증 절차와 증거

### 카드 1: 계획

- 사용자 실제 계획에 ID·기간·우선순위·성공 기준·예상 시간을 저장하고 다시 조회한다.
- 한 번 수정하고 같은 계획 ID 아래 원래 내용과 현재 내용이 각각 남는지 확인한다.
- 증거: 저장 화면과 계획 변경 이력.

### 카드 2: 업무

- 실제 업무 5개 이상으로 생성·수정·완료·되돌리기·삭제와 마감일·우선순위·태그·예상 시간을 확인한다.
- 검색·필터를 조합하고 정렬 기준과 동률 처리 기준이 화면 설명대로 유지되는지 확인한다.
- 증거: 각 상태 변경 결과와 검색·필터·정렬 결과. 삭제 항목은 일반 집계에서 제외하고 이력은 보존한다.

### 카드 3: 실행

- 시작·종료·실제 소요 시간·막힌 이유를 업무와 연결된 별도 실행 기록으로 저장한다.
- 실행 저장 전후 원계획을 비교하고 완료 요청을 연속 두 번 보내 기록과 완료 집계가 각각 한 번만 증가하는지 확인한다.
- 증거: 업무-실행 연결, 중복 요청 결과, DB 유일성/요청 중복 방지 검증. 버튼 비활성화만으로 통과 처리하지 않는다.

### 카드 4: 돌아보기

- 같은 대상 업무 집합으로 미삭제 업무 수·현재 완료 수·미완료 지연 수·막힘 업무 수를 직접 계산해 화면과 대조한다.
- 예상 합계와 실행 합계는 같은 시간 단위로 비교한다. 차이=실제−예상이며 빈 데이터는 0이다.
- 집계 숫자를 누르면 동일한 필터와 기준의 근거 기록이 열리는지 확인한다.
- 개선점 한 줄을 다음 계획에 전달하고 다음 화면에서 확인한다.
- 증거: 집계·근거 기록·다음 계획에 반영된 한 줄.

### 카드 5: 실제 자료·저장·제출

- 실제 계획 1개 이상, 연결 업무 5개 이상, 실제 실행 3개 이상은 사용자가 제공하거나 직접 입력한 사실만 사용한다. 테스트 fixture를 실제 기록처럼 제출하지 않는다.
- 사용자 자료로 집계가 채워짐을 확인하고 전체 자료를 파일 하나로 내보낸다. 새로고침 전후 ID·날짜·값·단위를 비교한다.
- 저장한 스크립트 형태 문자열이 실행되지 않는지 확인한다. 비밀값은 노출 없이 코드·산출물·응답·콘솔·Git 이력을 점검하고 이력이 없으면 해당 범위를 미존재로 기록한다.
- 결과물·소스 URL 각각을 새 시크릿 창에서 검사한다. 접근할 수 없거나 URL이 없으면 제출 검증 미완료로 남긴다.
- 증거에는 공개해도 괜찮은 데이터만 담는다.
