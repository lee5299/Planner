# AI 협업 시작 문서

이 폴더는 플랜두씨 다이어리의 요구사항과 작업 인수인계를 담는다. 이전 대화와 저장소 밖의 파일 없이도 목표와 작업 상태를 이해할 수 있도록 유지한다.

## 다른 AI에게 전달할 요청

아래 요청과 docs 폴더 전체를 함께 전달한다. 작업 범위는 사용자가 구체적으로 채운다.

> 첨부한 docs/README.md부터 읽고 PRD.md, DESIGN.md, WORK_LOG.md, CHECKLIST.md를 확인해 주세요. 이번 작업은 [작업 범위 또는 체크리스트 ID]입니다. 확정 요구사항을 유지하고, 현재 상태를 확인한 뒤 작업하세요. 코드를 수정해야 하는데 저장소나 소스가 없다면 필요한 자료를 구체적으로 요청하세요. 확인하지 않은 구현·테스트 결과를 만들어내지 말고, 완료 후 변경 파일과 갱신한 인수인계 문서를 함께 반환해 주세요.

docs만 전달하면 기획·검토·신규 구현의 요구사항을 공유할 수 있다. 기존 코드를 이어서 수정하거나 실제로 테스트하려면 해당 코드/저장소와 실행 환경 접근도 필요하다. docs는 코드 백업이 아니다.

## 읽는 순서와 문서 역할

1. README.md: 협업 절차와 작업 규칙의 원본.
2. PRD.md: 제품 목적, 확정 기능, 구현 기본값과 수용 기준.
3. DESIGN.md: 디자인 참고 출처, 스타일, 화면·상호작용 기준.
4. WORK_LOG.md: 현재 상태, 기술 정보, 다음 작업과 누적 이력.
5. CHECKLIST.md: 안정된 ID를 가진 검증 항목과 증거.

상위 시스템/개발 환경 지침을 준수하고, 현재 사용자의 명시적인 작업 범위와 변경 요청을 따른다. 제품 판단은 PRD의 확정 요구사항을 기준으로 하며 기본값을 확정사항처럼 취급하지 않는다. 디자인과 기능 문서가 충돌하면 확정 기능을 우선하고 충돌을 기록한다. 해결되지 않는 중대한 충돌만 질문한다. 로그의 옛 계획이 최신 요구사항을 덮어쓰지 않는다.

## 작업 시작

- 요청 범위, 관련 체크리스트 ID, 예상 변경 파일과 필요한 검증을 정리한다.
- WORK_LOG의 현재 상태를 실제 파일과 비교한다. 문서에 쓰였다는 이유만으로 구현 완료를 믿지 않는다.
- 기존 저장소가 있으면 지침, 변경 사항, 스택, 실행 스크립트와 DB 연결 방식을 확인한다. 소스가 없으면 미확인으로 기록한다.
- 기존 사용자 변경을 덮어쓰거나 확정 범위에 없는 기능을 추가하지 않는다.
- 이미 합의한 요구사항을 반복 질문하지 않는다. 접근 정보처럼 꼭 필요한 사항만 요청한다.

## 작업 종료와 자동 기록

코드·설정·문서를 생성/수정/리팩터링하면 별도 요청을 기다리지 말고 아래를 수행한다. 쓰기 권한이 없으면 수정본을 반환하고 반영되지 않았음을 명시한다.

1. 요구사항·디자인 변경은 해당 원본 문서에 반영하되 사용자 확정과 구현 제안을 구분한다.
2. CHECKLIST를 갱신한다. 구현만 된 상태와 실제 검증 통과를 구분한다. `[x]`는 검증 통과에만 사용한다.
3. WORK_LOG 상단의 현재 상태와 다음 작업을 최신으로 바꾸고, 아래 누적 이력에 새 항목을 추가한다. 기존 이력을 지우지 않는다.
4. 최종 보고에 변경 파일, 실제 검증 결과, 미완료/차단사항, 다음 작업을 적는다. 외부 AI는 수정한 코드와 문서 또는 적용 가능한 패치를 반환한다.

## 작업 로그 형식

현재 상태에는 구현 범위, 기술 스택/주요 경로, 실행·테스트 명령, DB·마이그레이션 상태, 필요한 환경변수 **이름만**, 마지막 검증, 알려진 문제, 다음 작업을 적는다. 모르는 것은 ‘미확인’으로 쓴다. 저장소가 있다면 작업 브랜치/커밋도 기록한다.

누적 항목 형식:

### [YYYY-MM-DD HH:mm 시간대] - 작업 요약
- 요청 범위/담당: 사용자 요청과 작업한 AI 식별명(알 수 있는 범위).
- 변경 파일과 핵심 내용: 경로, 변경 이유, 주요 인터페이스/데이터 구조.
- 검증: 명령/절차, 결과, 관련 CHECKLIST ID. 미실행이면 사유.
- 현재 상태와 다음 작업: 완료/미완료, 다음 AI가 시작할 구체적인 작업.
- 결정 및 제약: 변경한 기본값, 호환성, 필요한 자료. 없으면 없음.

## 병렬 협업 시

병렬 작업은 사용자가 요청했거나 현재 실행 규칙에서 허용할 때만 한다. 이 문서 자체가 AI 추가 실행을 명령하지 않는다. 작업별 담당 범위·파일·입출력 인터페이스를 먼저 합의하고 같은 파일의 동시 수정을 피한다. 통합 담당자가 변경 사항과 문서, 검증 결과를 합치며 외부 AI의 통과 보고는 증거와 코드 상태를 확인한다.

## 유지 원칙

- 문서 경로는 프로젝트 상대 경로로 쓰고 파일명 대소문자를 맞춘다.
- 비밀번호, 토큰, 연결 문자열의 비밀값은 저장하지 않는다.
- 이 폴더는 5개 문서를 기본으로 유지한다. 작업마다 별도 보고서를 무분별하게 만들지 않는다.
- 제품 핵심은 자기관리/프로젝트 완전 분리, 자기관리 숫자 평가 숨김, 프로젝트 객관적 정리, 실제 DB 저장이다.
